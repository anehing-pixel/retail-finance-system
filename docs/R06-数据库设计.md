## 1. 引用口径

- 所有金额列 `BIGINT`（日元）；比率 `NUMERIC(7,4)`；时间 `TIMESTAMPTZ`；业务日期 `DATE`。
- 枚举列 `VARCHAR(24/32)`，转换在持久层（共享 `RowValues` + 各服务仓储），`domain` 不感知。
- 表名、列名一律小写 `snake_case`；唯一索引 `uk_<表>_<列>`；普通索引 `idx_<表>_<列>`。
- **不物理删除、不软删标记**；生命周期由状态列表达；审计 append-only。
- PII 列名一律 `encrypted_*` 或 `*_hash`，禁止明文列；见 §5。
- 每张表标注**权威写者**（`R02 §6`），其他模块不得直写。

## 2. 全局约定（公司级中台标准，与 floorplan 一致）

| 约定 | 规则 |
|---|---|
| 金额 | `BIGINT` 整数日元；禁止 `double/float`；比率 `NUMERIC(7,4)`，量化后落金额 |
| 时间 | `TIMESTAMPTZ` 全系统 JST；`created_at` / `updated_at` 必带；业务日期 `DATE` |
| 主键 | `BIGSERIAL`；另建业务唯一键（如 `application_no` / `contract_no` / `loan_no`） |
| 枚举 | `VARCHAR`，`CHECK` 约束仅用于稳定枚举；值与 `R00 §3.4` 一致 |
| 并发 | `version INT NOT NULL DEFAULT 0` 乐观锁；额度/债权读改走 `SELECT ... FOR UPDATE` |
| 幂等 | 写表带 `idempotency_key VARCHAR(64)` + 唯一索引；批处理 `(job_name, biz_date)` 唯一 |
| 审计 | `audit.audit_events` 仅授 INSERT；`actor` 取验签身份；`actor_subject` 四类 |
| 删除 | 禁止 `DELETE`；不建 `is_deleted` 列 |
| 快照 | 征信查询结果、审查决定、余额快照 **append-only**，历史不重算 |

## 3. schema 分区与授权（PII 隔离是硬要求）

```
retail_finance (PostgreSQL 16 :5435)
├── core          业务主数据、账务、还款、所有权（retail_app_rw）
├── pii           个人敏感信息（retail_pii_rw，独立 role）
├── integration   DMZ 集成流水与凭据（retail_dmz_rw）
└── audit         审计与 PII 访问日志（app_rw 写 audit_events；pii_rw 写 pii_access_logs；audit_ins 专用/归档）
```

| role | 授权 | 说明 |
|---|---|---|
| `retail_app_rw` | `core` 全表 + `pii.customers` 只读（**不含 `pii.customer_pii`**）+ `audit.audit_events` INSERT/SELECT（G-DB-7） | 业务进程主角色 |
| `retail_pii_rw` | `pii` 全表 + `audit.pii_access_logs` INSERT/SELECT（G-DB-7） | **仅 `PiiService` 使用**，独立连接池 |
| `retail_dmz_rw` | `integration` 全表；**不授 `core` / `pii`** | `external-api` 独立进程 |
| `retail_audit_ins` | `audit` 两表 INSERT/SELECT | 审计专用/归档账号；append-only 保证 |

> 注：`retail_app_rw` 在 pii schema 的读权限已按 **V16 / V17** 收至只剩 `pii.customers` 只读——`pii.customer_pii`（V16）与
> `pii.consents` / `pii.consent_withdrawals` / `pii.identity_verifications` / `pii.identity_documents`（V17）均已撤销；
> V1 的 pii schema 级默认授权同步撤销，此后新建 pii 表默认不授予业务角色；
> 报发送量锚定走 `core.v_recon_inv5_consent` 视图（owner = postgres，以视图属主校验底层表权限），业务角色不受影响。

### 3.1 连接账号口径：隔离何时真正兑现（2026-11-23 用户口径）

> **本地 11 个连库单元（10 业务服务 + DMZ；网关不连库）统一以 `postgres` 超级用户连库**
> （各服务 `application.yml` 的 `spring.datasource.username` 默认值即 `postgres`；
> `run-microservices.sh` 以 `POSTGRES_PASSWORD=postgres` 建容器）。
> 超级用户绕过全部 ACL，因此 §3 的四个角色授权位**在本地不被行使**：本地用超级用户直查
> `pii.customer_pii` **不会**报权限错误。
> **结论：DB role 隔离是生产侧的物理兜底，不是本地已生效的运行态控制。**

| 项 | 口径 |
|---|---|
| 隔离载体 | **连接账号**——角色与账号一一对应，账号即权限边界；只建角色不分配账号，授权位不生效 |
| 生效条件 | 运行期连接使用**按角色分配的受限账号**登录，授权位才在数据面真正拦截 |
| 本地现状 | 统一超级用户 → 本地只能验证**授权位配置正确**（系统目录查询），**无法验证「越权被拒」** |
| 生产兑现 | 按角色分配账号 + 迁移账号与运行账号分离后，`R08 PII-5` / `R10 A23` 的物理兜底才成立 |
| 迁移账号 | Flyway 需 owner/超级用户（建 schema、建表、授权），`retail-core` 的**迁移连接与业务运行连接必须分账号**；本地为简便合并为超级用户 |
| 口令 | V1 建角色时写入的是开发口令（`*_dev`），生产必须换为密钥托管的强口令，不得沿用 |

**明确不做（本地）**：本地不按角色分配连接账号。本地验证的目标是**业务链路与口径**，不是**越权拦截**；
把「本地绿灯」表述成「生产隔离已生效」是本项目明令禁止的说法（`PROGRESS §7` 第 7 条）。

### 3.2 投产门禁 G-DB（上线前逐条满足，fail-closed）

> **门禁性质**：**fail-closed**——任一项不满足，**生产部署不予放行**（`AGENTS §5`：编译通过 ≠ 交付）。
> **执行时机**：外部对接与合规验收阶段收口前，在**具备受限账号的类生产环境**执行一次完整实测并留证。
> **本地可做 / 本地不适用**：G-DB-5（越权拦截）**本地可执行**——用角色口令直连容器执行 SQL 即可验证，
> 不必改服务连接池（V17 轮已实测 13/13 符合设计）；G-DB-2 / G-DB-6（服务运行连接按角色分配、业务流量禁用超管）
> **本地不适用**——本地 11 个连库单元仍统一超级用户（§3.1）。**本地全绿不构成门禁通过证据**。

| # | 门禁项 | 判据（可核验） | 当前状态 |
|---|---|---|---|
| **G-DB-1** | 四角色各配**独立登录账号** | `pg_roles` 实查四个角色 `rolcanlogin=true`；**口令不得沿用 V1 的 `*_dev`**，须由密钥托管注入 | ⬜ 未开始 |
| **G-DB-2** | 运行连接**按角色分配** | 11 个连库单元的 `spring.datasource.username` 指向对应受限账号：业务服务 → `retail_app_rw`；PII 访问 → `retail_pii_rw`；`external-api` → `retail_dmz_rw` | ⬜ 未开始 |
| **G-DB-3** | **迁移账号与运行账号分离** | Flyway 用 owner/超级用户账号（仅迁移期使用）；运行期账号**不得持有 DDL 权限**（无 CREATE/ALTER） | ⬜ 未开始 |
| **G-DB-4** | 默认权限**绑定迁移账号** | `ALTER DEFAULT PRIVILEGES` 按**创建者角色**生效，须以迁移账号设置，否则新建表不自动授权；`pg_default_acl` 实查：`pii` 默认只授 `retail_pii_rw`、`core` 默认授 `retail_app_rw` | ⬜ 未开始 |
| **G-DB-5** | **越权拦截实测**（`R10 A23` 转正） | 以 `retail_app_rw` 连接直查 `pii.customer_pii` → **权限拒绝**；以 `retail_pii_rw` 连接可查 | ✅ **本地已实测**（V17 轮：角色口令直连容器，13/13 符合设计；服务自身连接池仍为超管） |
| **G-DB-6** | 业务流量**禁用超管账号** | 运行期连接池的用户**不得**为 `postgres` 等超级用户；超管仅用于迁移与运维排查 | ⬜ 本地不适用（生产兑现） |
| **G-DB-7** | **审计写入账号归属落地** | 原缺口：V1 只把 INSERT 授 `retail_audit_ins`，单连接池下切受限账号后 `servicing-service` / `customer-service` 审计写入会失败。已按 `G-DB-2` 实际连接角色做等效授权（`retail_app_rw` → `audit.audit_events`；`retail_pii_rw` → `audit.pii_access_logs`），且**未放开 UPDATE / DELETE / TRUNCATE** | ✅ 已完成（2026-11-24，**V21**；三角色权限实测） |

**G-DB-7 落地方案（架构侧裁决 2026-11-23；2026-11-24 按 G-DB-2 连接角色细化）**：
按**实际写入方各自的连接角色**授权，不改代码、不开第二连接池——
`servicing-service`（`retail_app_rw`）对 `audit.audit_events`、`customer-service`（`retail_pii_rw`）对 `audit.pii_access_logs`
各授 `INSERT`/`SELECT` + 序列 `USAGE`/`SELECT`；`retail_audit_ins` 保留两表 `INSERT`/`SELECT`（审计专用/归档）。
两表对所有运行角色**显式禁止 `UPDATE` / `DELETE` / `TRUNCATE`**，append-only 保证不变。
**升级条件**：若生产合规要求「审计写入身份与业务身份彻底分离」，再拆独立审计账号 + 独立连接池，届时须改造 `common` 审计写入层。
该授权调整走**新迁移 V21**（`V21__g_db_7_audit_write_authorization.sql`；V20 已被 MQ 密文信封通道占用、V19 已被回调幂等唯一索引占用，见 §6），不改已执行迁移字节。

**硬规则**：
- `retail-core` 的业务代码**不得直查 `pii.customer_pii`**，只能经 `PiiService` 接口；由 DB role 在物理层兜底（`R03 §4` 切断点 ③ 的数据面）——**该兜底在按角色分配连接账号后才于运行期生效，见 §3.1**。
- `integration.inbound_messages` 原始报文**不落 PII 明文**，必要时存引用 + 脱敏摘要。
- `audit.pii_access_logs` 记录「谁 / 何时 / 访问哪个 customer / 哪个字段 / 用途」，不记明文值。
- 附件（身份核验材料 / 收入证明 / 解除文件）存**本地文件系统** `data/attachments/`，DB 只存 `core.attachments` 的相对路径与哈希（`ADR-RF-008`）。

## 5. PII 加密与访问管控（`ADR-RF-004` / `ADR-RF-008`）

| 控制 | 规格 |
|---|---|
| 字段级加密 | 姓名 / 住址 / 出生日期 / 电话 / 工作单位 / 年收入 用 **AES-256-GCM**，每字段独立随机 IV；密文 `BYTEA` |
| 检索 | 需精确检索的字段另存 **HMAC-SHA256** `name_hash` / `phone_hash`，**不存明文、不用确定性加密** |
| 密钥 | 独立 `PII_DATA_KEY`（**与 JWT 密钥、账号加密密钥分离**）；**配置无默认值**，缺失 / 过短 / 与 HMAC 密钥复用即启动失败（`R11 P0-8`）；`key_version` 支持轮换，旧版本保留至存量数据重加密完成；托管与自动轮换仍属上线运维项 |
| 脱敏 | 展示层 `mask()`：姓名只显姓、电话末 4 位、地址到市区；默认返回脱敏 |
| 全量查看 | `PII_VIEW_FULL` 权限 + 用途 + 二次确认 + `pii_access_logs` 留痕 |
| 生命周期 | `[待定源 C-06]` 默认保留 5 年；到期走**匿名化/删除作业**，审计链保留但去除可识别信息 |
| 个人编号 | **默认不采集**（L-8）；如法务要求另建隔离域，不并入 `customer_pii` |
| 附件 | 身份核验材料 / 收入证明存本地 `data/attachments/`，按 `biz_id` 分目录，权限受 OS ACL + 应用鉴权双重控制 |
| 事件/日志 | outbox payload、应用日志、对外报文**一律不含 PII**（INV-4、`R09 §5`） |
| MQ 载荷 | **只允许密文信封**（8 键白名单）；明文载荷不入队（`ADR-RF-014`、`R09 §5.5`） |
