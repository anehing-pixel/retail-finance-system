## 4. 断言清单（A1 – A30）

### A 组：五条可证伪不变式（A1–A8）

| # | 断言 | 对应 |
|---|---|---|
| A1 | 同一 `contractId` 用不同幂等键重复代付 → 第二笔被拒，账本无第二条 | INV-1 |
| A2 | 部分还款 / 超额入金 / 提前结清后，余额对拍**精确相等**（不容差） | INV-2 |
| A3 | 归档/快照后取数仍精确相等（不因「只查主表」报假差异） | INV-2 |
| A4 | 未结清创建 `ReleaseOrder` → `RF_TITLE_001` / 422 | INV-3 |
| A5 | 伪造 `PARTNER_SELF_REPORT` 回执 → 不得进入 `RELEASE_REGISTERED` | INV-3 |
| A6 | 扫描全部 outbox payload 键，白名单外命中即失败 | INV-4 |
| A7 | 撤回同意后发起查询 → `RF_UW_003` 被拒；报送同样阻断 | INV-5 |
| A8 | 无 `consent_id` 的 `CreditInquiry` / `CreditBureauReport` 无法落库（DB 非空约束） | INV-5 |

### B 组：十一道闸门（A9–A14）

| # | 断言 |
|---|---|
| A9 | G1 缺同意 / 重复申请 → 拒绝受理，幂等返回首次结果 |
| A10 | G3 同意撤回 → 立即中止查询，`CONSENT_WITHDRAWN` 秒级送达消费方 |
| A11 | G4 查询超时 → 3 次重试后转人工，**不写空结果**、不留 `INQUIRY_DONE` 假状态 |
| A12 | G6 申请人与复核人同一自然人 → `RF_AUTH_003` 硬阻断（SOD） |
| A13 | G7 书面文件未交付 → 不得 `SIGNED`（`RF_CTR_001`） |
| A14 | G8 门禁任一 UNKNOWN / 超时 → **fail-closed 拒绝代付**，整体回滚 |

### C 组：解押闭环与证据链（A15–A20）

| # | 断言 |
|---|---|
| A15 | `DOCUMENTS_ISSUED` 后 `TitleRetentionStatus` 仍为 `REGISTERED`（两态分离） |
| A16 | `MANUAL_RECORDED` 不得直达 `REGISTRATION_CONFIRMED`，须补外部回执 |
| A17 | 证据链八条缺任一 → `/evidence-chain` 报未闭合，不得改写保留状态 |
| A18 | 回执权威分级：`EXTERNAL_REGISTRY` > `INTERNAL_WITNESS` > `PARTNER_SELF_REPORT`（后者拒采） |
| A19 | 回执超时 → 工单 + 状态停留，不自动完成 |
| A20 | 解押完成后征信报送终态已发，且 `CREDIT_BUREAU_REPORT_SENT` 可追溯 |

### D 组：PII 与合规（A21–A25）

| # | 断言 |
|---|---|
| A21 | 客户 token 访问员工端点 → 401/403；员工 token 访问客户端点 → 401/403 |
| A22 | 审计 `actor_subject` 能区分 CUSTOMER / STAFF / SYSTEM / PARTNER |
| A23 | `retail_app_rw` 直查 `pii.customer_pii` → 权限拒绝（DB role 兜底） |
| A24 | 日志 / `call_logs` / 对外响应扫描 PII 明文 → 零命中 |
| A25 | `PII_VIEW_FULL` 全量查看产生 `pii_access_logs` 记录，且日志不记明文值 |

### E 组：幂等与并发（A26–A28）

| # | 断言 |
|---|---|
| A26 | 同 `Idempotency-Key` 重放返回首次结果；键同体不同 → `RF_CONFLICT_001` |
| A27 | 20 并发入金核销：余额精确、无重复核销、无丢失更新（行锁 + 唯一约束） |
| A28 | 批处理重跑（同 `jobName+bizDate`）不产生第二份数据 |

### F 组：中台切断点（A29–A30）
