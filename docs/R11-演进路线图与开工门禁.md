## 1. 引用口径

- 阶段 **S0–S5**、工作包 **W1–W9**（W6‖W7 并行窗口、W8 E2E 收口、W9 收尾三包为执行期扩展，进度以 `PROGRESS.md` 为准）、
  需求/断言编号沿用 `R01`/`R10`，不另起体系。
- **不写人月 / 日历工期估算**：外部方真实能力未经对方确认（我方内部裁决见 `R07 §3 §7`），估了也是假精度（`R07 §8`）。
- 阶段门禁是**硬门槛**，不是建议；未满足不得进入下一阶段。
- `§2.1` 生产就绪清单是**投产门禁的展开**：P0 / P1 / P2 分级 + 模块视角差距，两种视角指向同一批门禁项，不重复计。
- 「工作包」= 可独立交付的服务/能力集合；「并行窗口」= 互不共享写入集的服务组合。
- 实时状态以 `PROGRESS.md` 为准，本文件的勾选不随开发更新。
- 全文中文；服务名、表名、枚举、配置键保留英文标识符。

### 2.1 生产就绪清单（投产门禁展开）

> **性质**：这是**投产门禁的展开**，不是愿望清单。分级口径：
> **P0 = 不满足不得放行**（含「上线前必绿」与「单实例豁免 / 扩容前必绿」两档豁免条件）；
> **P1 = 上线前（T-1）或灰度期（T-2）必须闭环**；**P2 = 常态运营期（T-3）持续建设**。
> **审计基线**：2026-11-24（P0-1 后复核）· Flyway **V1–V22（22 条迁移，V20 = MQ 密文信封通道，V21 = G-DB-7 审计写入授权，V22 = G-DB-2 运行期受限角色补偿授权）** · **18 个 Maven 模块**（状态机引擎底座 + 独立 `db-migration` 迁移作业）· `retail_finance` 四 schema 62 表。
> **两种读法**：① 按**主题**看 P0 / P1 / P2（§2.1.1–§2.1.3）；② 按**模块**看逐模块差距（§2.1.4）。二者指向同一批门禁项，**不重复计**。
> **红线**：本清单**不降低** `AGENTS.md` §3 的 B-1~B-13 与 `R06 §3.2` 的 fail-closed 口径；清单项全绿 ≠ 业务口径已签字。

#### 2.1.6 与现实差最远的六件事（放行决策必读）

1. **C 端真实认证不存在**：客户侧登录是开发桥（默认关），双主体模型只有员工侧真正落地。

5. **个人信息与令牌密钥带弱默认值**：漏注入即静默使用弱密钥，配置层没有「缺失即失败」。
6. **最危险的机制缺测试**：投递器与共享 `domain` / `application` 三处**零单测**；对拍模块仅 1 个测试类。

> 当前唯一使用方是 `retail-core` 的产品档位目录（只读业务配置），**符合 `AGENTS.md` B-13 与 `ADR-RF-012` 白名单**；

## 4. 并行窗口与跨项目节奏协调

### 4.1 内部并行窗口（多服务）

```
W1(串行) → W2(串行，冻结契约/号段/路由)
```

**四处硬耦合（决定边界）**：

4. **Feign 契约与事件名**由 W2 冻结在 `common/contract`；并行包只能消费、不得自行新增未登记契约。
