## 2. 术语定名表（强制口径）

> ⚠️ 中文项目描述里的「抵押 / 解押 / 借钱给消费者」是**简化表述**，在本系统内一律按下列**中文定名**落地。
> 本仓文档全文使用中文：法律与机构名用中文译名，不混写日文表记；需要查证日文原文时以法务意见书为准。
> 「常见误写」列只列出容易写错的中文词，用于纠错，**不是第二套命名**。

| # | 中文定名 | 常见误写 / 别名 | 定义与边界 |
|---|---|---|---|
| 1 | **信贩公司 / 我方** | 信用卡公司 | 第三方非银金融机构；本项目主体 |
| 2 | **消费者 / 客户** | 购买人 / 债务人 | **自然人**；本项目的借款 / 分期主体 |
| 3 | **销售店 / 4S 店 / 加盟店** | 经销商 | 与 floorplan 的「经销商」是**同一批法人**，但本项目里是加盟店 / 代付对象 / 申请代办，**不是债务人** |
| 4 | **申请** | 信用购买申请 | 消费者（经店端或门户）提交的申请，聚合 `Application` |
| 5 | **审查 / 授信** | 审查判断 | 征信查询 + 收入证明 + 支付能力预估额 + 在职确认 + 反社会势力排查 |
| 6 | **个品分期 / 个别信用购买斡旋** | 分期付款销售 | **主形态**：信贩向销售店代付，消费者向信贩分期支付；《分期付款销售法》 |
| 7 | **汽车贷款** | 直接贷款 | 备选形态：直接放款；《贷金业法》（总量规制 / 除外贷款） |
| 8 | **代付** | 车款清偿 | 信贩把车款付给销售店；**不是把钱打给消费者** |
| 9 | **所有权保留** | 抵押权 | 结清前信贩（或销售店）为车辆检验合格证「所有者」；**不是抵押权** |
| 10 | **所有权解除 / 名义变更** | 解押 | 结清后出具解除文件并办理登记；**两态分离**，见 `R04 §4` |
| 11 | **解除文件** | 所有权解除同意书 / 转让证明书 / 授权委托书 / 印鉴证明书 | 文件出具 ≠ 登记完成 |
| 12 | **账户自动扣款** | 自动扣款 | 主要收款方式；设定完成约需 2 个月 |
| 13 | **缴款单** | 汇款单 | 账户自动扣款未生效时首期 / 过渡收款，以及便利店代收 |
| 14 | **提前结清** | 一次性结清 | 中途一次性结清；金额 = 剩余本金 − 约定减免额 + 事务手续费 |
| 15 | **支付能力预估额** | 个别支付能力预估额 / 综合支付能力预估额 | 《分期付款销售法》下的防止过度授信基准；与《贷金业法》总量规制（年收入 1/3）**不是同一个数** |
| 16 | **个人信用信息机构** | CIC / JICC / 全国银行个人信用信息中心 | CIC 同时是《分期付款销售法》与《贷金业法》下的**指定信用信息机构** |
| 17 | **查询 / 登记 / 异议申诉** | 合同内容与还款状况登记 | 征信机构三条链路，见 `R07 §4` |
| 18 | **身份核验** | 交易时确认 / eKYC | 驾驶执照 / 个人编号卡等 |
| 19 | **法定书面文件** | 缔约前书面文件 / 合同书 | 《分期付款销售法》/《贷金业法》要求的书面交付义务 |
| 20 | **冷静期** | — | 个品分期下的解约权；期间与例外需法务定源 |
| 21 | **DMS** | 经销商管理系统 / 销售店核心系统 | 店端系统：申请报送、审查结果接收、代付请求、交车报告 |
| 22 | **名义变更完成** | 所有者变更登记完成 | 运输支局 / 轻型汽车检查协会登记完成，回执为权威 |
| 23 | **加盟店合同** | 代办合同 | 信贩与销售店的合作合同，与 floorplan 的融资合同**分开管理** |
| 24 | **个人信息（PII）** | 个人数据（APPI） | 姓名 / 住址 / 出生日期 / 电话 / 工作单位 / 年收入 / 身份核验材料 / 账户 等 |
| 25 | **车辆检验合格证** | 机动车检验合格证 | 所有者栏是所有权保留的登记载体 |

**禁用词**：本仓文档与代码禁止使用「抵押登记」「抵押权抹消」「押车」「合格证」「在库车辆台账」描述 C 端业务
（这些是 floorplan B 端语义）。如需对照，必须写明「floorplan 侧用语」。

> **语言口径**：法律与机构名用中文译名（如《分期付款销售法》《贷金业法》《个人信息保护法》）；
> 服务名、表名、配置键、代码标识符与拉丁缩写（`retail-core`、`DMS`、`CIC`、`JICC`、`APPI`、
> `PII`、`JWT`、`ApiResponse<T>` 等）保留原样；ADR 状态标签 `Accepted` / `Proposed` 沿用架构决策记录惯例，
> 视为固定标签保留。本表是全仓唯一命名权威源，其他文档只引用、不新造。

## 4. 设计原则 P-1 ~ P-12

| # | 原则 | 落地约束 |
|---|---|---|
| **P-1** | **领域优先于技术** | 先把「交易形态 / 所有权保留 / 支付能力预估额」定清楚，再谈表与服务 |
| **P-2** | **机制复用、语义隔离** | 中台只共享机制层；法人/VIN/让渡担保语义一律不进本项目（`R03`） |
| **P-3** | **可逆性优先** | 起步内聚，拆分写触发器；不把「最优」凌驾于「易改」 |
| **P-4** | **账务事务红线** | 核销 + 解押触发 + 债权状态迁移同一本地事务；禁止分布式事务 |
| **P-5** | **每类数据一个权威写者** | 明写 `R02 §6` 真相源表；禁止跨上下文直写他域表 |
| **P-6** | **PII 最小面** | 独立 schema、字段级加密、不进 outbox/日志/对外报文、访问留痕 |
| **P-7** | **双主体不混用** | 客户与员工两套身份、两套 token、审计区分主体类型 |
| **P-8** | **外部必经 ACL** | DMS / 征信 / 支付 / eKYC 的 DTO 不直落领域对象；人工路径一等公民 |
| **P-9** | **两态分离** | 「文件出具」≠「登记完成」；「発行」≠「完成」的所有类似场景同此 |
| **P-10** | **同步只做门禁（fail-closed）** | 审查/放款前的必要校验失败一律拒绝；事后同步走 outbox |
| **P-11** | **不把占位说成已实现** | 四状态标强制使用；文档规格 ≠ 代码事实 |
| **P-12** | **口径变更走配置不改代码** | 已签字参数入配置/规则表；不新造「待确认」状态 |

## 5. 公司级中台标准（两项目共同的最大公约数，无冲突）

| 约定 | 规则 |
|---|---|
| 金额 | `BIGINT` 整数日元（Java `long`）；比率/利率 `NUMERIC(7,4)`；量化后落金额；禁止 `double/float` 参与金额 |
| 时间 | `TIMESTAMPTZ`，全系统 JST（`jackson.time-zone: Asia/Tokyo`）；业务日期 `DATE`；禁止 `new Date()` 直接入库 |
| 主键 | `BIGSERIAL`；业务键另建唯一索引 |
| 枚举 | DB `VARCHAR`，枚举↔字符串转换放持久层（共享 `RowValues` 与各服务仓储），`domain` 不感知 DB 类型 |
| 删除 | **不物理删除、不软删标记**；生命周期用状态字段表达；审计 append-only |
| 并发 | `version` 乐观锁 + 额度/债权 `SELECT ... FOR UPDATE` 行锁；禁止无锁读-改-写 |
| 审计 | `audit.audit_events` append-only、仅授 INSERT；`actor` 取**验签身份**；`actor_subject` 区分四类主体；含 `trace_id` / 前后快照 |
| 幂等 | 写接口 `Idempotency-Key` + DB 唯一索引双兜底；批处理 `(biz_date, job_name)` 唯一约束；键同体不同 → `RF_CONFLICT_001` |
| 状态变更 | 走聚合状态机方法，禁止直接 `UPDATE ... SET status` |
| 响应 | 统一 `ApiResponse<T>`（`code/message/data/traceId/details`）；`202` ≠ 业务成功 |
| 日志脱敏 | PII 字段白名单脱敏；**禁止打印 PII 明文**（`R08 §5`） |
