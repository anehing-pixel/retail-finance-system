## 状态

**Accepted**（2026-11-22，业务方裁决 `[待定源 C-01]`：**双形态并行**） · 影响：`R01`、`R04`、`R07`、`R08`、`R11 §8`
> 本 ADR 裁决的是**产品形态**（业务做哪几种）。**适用法规与业者登记形态仍属 `[待定源 C-02]`，必须由法务意见书给出**；本 ADR 不冒充法务结论。

## 背景

用户描述为「**借给 C 端消费者（买新车）**」「**还清贷款后解除抵押**」。
但日本信贩公司新车零售金融的主流实务是 **个品分期（个别信用购买斡旋）**：

- 信贩**向销售店代付**（代付车款），消费者向信贩**分期支付** —— 钱不是打给消费者；
- 担保是**所有权保留**（车辆检验合格证「所有者」栏为信贩），不是抵押权；
- 「解押」实务是**所有权保留解除 + 名义变更**，且「文件出具」≠「登记完成」；
- 适用法规为分期付款销售法（而非贷金业法），额度基准是**个别支付能力预估额**，有法定书面文件与冷静期。

备选形态是**汽车贷款**（汽车贷款）：直接贷付、贷金业法、总量规制（年收入 1/3，但汽车贷款
可能属除外贷款）、指定信用信息机构查询义务。

**已核实的关键事实**（`R01 §2.4`）：无论哪种形态，**征信查询都是刚性需求** ——
CIC 同时是分期付款销售法与贷金业法的指定信用信息机构；分期付款销售法下个别信用购买斡旋业者亦负
个别支付能力预估额调查义务。因此「是否对接征信局」不随形态变化。

## 结论

1. **双形态并行首发**：`TransactionScheme` 枚举两个值同时上线——`INSTALLMENT_CREDIT`（个品分期）
   与 `MONEY_LENDING`（汽车贷款）；**每笔申请必填形态字段，不设兜底默认**；不写两套系统。
2. 形态差异**收敛进 4 个策略点**，其余链路共用：

| 策略点 | 上下文 | 承载差异 |
|---|---|---|
| `StatutoryDocumentPolicy` | contract | 法定书面文件模板、交付时点、记载事项 |
| `AffordabilityPolicy` | underwriting | 支付能力预估额 / 总量规制 / 除外贷款 |
| `CreditBureauReportingPolicy` | reporting | 机关组合、报文、周期、异议路径 |
| `SettlementCalculationPolicy` | loan | 结清/提前结清金额、减免额、手续费 |

3. **共同链路（不受形态影响）**：申请 → 身份核验 → 同意 → 征信查询 → 审查 → 合同 →
   代付/放款执行 → 交车 → 所有权保留 → 还款计划 → 入金核销 → 结清 → 解除 → 报送。
4. 法务效力判断标 `[待定源 C-02/C-03/C-08]`，**只给接口与配置框架，不写死公式**；
   `C-01` 已签字（2026-11-22：双形态并行），S1 的该项开工门禁解除（`R11 §6`）。

## 后果

**变容易**：双形态并行下再新增/调整形态只需替换 4 个策略实现；共同链路的设计在 S0 就能全部完成，
**S1 地基与 S2 账务主干零返工**（`R11 §8` 保留为历史记录）。

**变难**：4 个策略点必须严格隔离，任何一处把形态判断扩散到全链路（例如 `if (scheme == ...)` 散落在
Controller / SQL / 状态机里）都会让本 ADR 失效；需要代码评审与断言守护。

**明确不做**：不把「个品分期」写成不可变更的法律结论；不实现总量规制/书面文件/冷静期的
法务效力判断；不因未签字就悬空架构（内部决策直接裁决，外部事实不凭空对接）。

## 被拒选项与理由

| 选项 | 理由 |
|---|---|
| 按用户字面做「直接借钱给消费者 + 抵押」 | 与日本信贩实务不符；资金流、担保、书面文件、报送全错，且属合规事故级返工 |
| 只做个品分期、写死单一形态 | 双形态是用户明确裁决；写死单一形态 = 需求覆盖不全 |
| 两套系统并行（A 形态一套、B 形态一套） | 成本翻倍、共同链路重复、维护不可控 |
| 等 C-01 签字后再设计 | 共同链路与形态无关，可以且应该先行；等待只会让 S0 空转 |

## 权衡

放弃「按字面最快出原型」，换取**法务签字后的低返工**。
这是一次典型的「把不确定性收敛到少数可替换点」的决策：不猜结论，但也不让猜测阻塞所有工作。
