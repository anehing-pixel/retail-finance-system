# ADR-RF-011：DMS 对接模式 — 数据集成商起步，核心集团直连演进

## 状态

**Accepted**（2026-11-22，业务方裁决：初期采用数据集成商模式） · 影响：`R07`、`R06`、`R09`、`PROGRESS`、`R11`

## 背景

DMS（经销商管理系统）是连接销售前端与金融后端的核心枢纽：对信贩公司而言，它既是获客入口，
也是自动化审批、放款与物权控制的关键通道。业务方已回填 DMS 对接口径（`R07 §3 §4 §7`），
核心业务接口四类：

1. **资质预审（事前查询）**：销售顾问在 DMS 录入客户基本信息并选择金融方案时触发；
   秒级返回预审结果（通过/拒绝/需人工）、预估额度、建议利率。
2. **正式授信申请（正式审查）**：正式购车订单生成后触发；在预审基础上增加车辆信息
   （车辆识别码、车型、新车/二手车标识）、合同金额、首付金额、产品形态（个品分期 / 汽车贷款）；
   后台发起征信查询并结合风控模型输出终审结果回传。
3. **电子合同与签约**：电子签名数据 / 合同 PDF / 身份证明文件；合同生效后触发代付
  （个品分期，付给销售店）或放款（汽车贷款，付给消费者）。
4. **余额与物权状态同步**：按月定时 + 异动实时（提前结清、逾期、代位清偿）；
   保证 DMS 车辆状态和信贩账务一致；结清时通知 DMS 解除物权限制，触发运输支局解押流程。

对接路径两条，各有代价：

- **直连**：与各 DMS 厂商逐一开发接口。实时性高、无中间费用；但需维护多套接口，开发成本高。
- **数据集成商**：集成商把不同 DMS 的原始数据标准化后统一推送。开发周期短、覆盖门店广；
  但存在数据延迟与集成费用。

## 结论

1. **初期（S3 起）采用数据集成商模式**：`external-api`（DMZ）只对接**一家集成商 partner**，
   不与各 DMS 厂商分别建通道。
2. **架构预留直连演进位**：per-partner Adapter 框架（`R07 §2.2`）天然支持后续为大型经销商集团
  （如丰田系）逐个增设直连 Adapter；切换按集团进行，不动公共框架。
3. **四类业务接口映射到契约清单**：资质预审 → `I-11`（Inbound）；正式授信申请 → `I-01`（Inbound）；
   审查结果回传 / 交车与代付请求 → `I-02` / `I-03`；余额与物权状态同步 → `I-12`（Outbound）。
4. **合规与技术护栏**（沿用既有设计，不因集成商模式放宽）：
   - 资质预审**不得触发征信查询**——预审时无正式同意（RB-1：同意缺失不得发起查询），
     只做内部规则与额度预判；
   - 传输 HTTPS/TLS 1.2+；per-partner HMAC 数字签名 + nonce 防重放（`R07 §5`）；
   - 全部写操作幂等（`Idempotency-Key`）；错误码统一 `RF_*` 前缀（`R09 §4`），
     业务语义错误映射 `RF_DMS_*` 段（如资质不符、车辆重复申请，对应集成商语义 AUTH_FAILED / VIN_DUPLICATE）；
   - 日本本土化字段：假名姓名（全角/半角、片假名/平假名）加密存储（`R06 §4.1` 增列）；
     驾照号格式前置校验；印鉴证明书扫描件走本地附件（`ADR-RF-008`）。

## 后果

**变容易**：单一 partner、单一报文标准，S3 集成层工作量可控、渠道铺开快；
`external-api` 的验签/幂等/对账体系只需服务一个对方；后期直连由 Adapter 框架承载，切换成本收敛为一个实现。

**变难**：
① 数据经集成商中转存在**延迟**——对账与状态同步必须以「我方账务为权威、DMS 侧为投影」设计，
不能反向依赖 DMS 状态；
② 集成商成为**渠道单点依赖**，人工路径与对账兜底（`R07 §2.4 §2.5`）必须长期保留；
③ 集成费用是长期成本，规模上来后核心集团需转直连降本。

**切换触发器**（登记进 `R11`）：某大型经销商集团月申请量达到业务阈值、或集成商对该集团的
延迟/字段覆盖不满足业务要求时，为该集团新建直连 Adapter。

**明确不做**：不因集成商模式把 DMS 报文直接落领域对象（ACL 强制不变）；
不在资质预审里做征信查询；不把集成商侧数据当成账务权威。

## 被拒选项与理由

| 选项 | 理由 |
|---|---|
| 初期即与各 DMS 厂商直连 | 多套接口并行开发，成本与工期不可控；新进入者渠道铺开慢 |
| 全部人工表格交换 | 无自动化审批/放款/物权控制，业务价值不成立；仅保留为兜底路径 |
| 只做集成商、永不直连 | 核心大集团实时性与定制字段要求高；长期费用与议价主动权受损 |

## 权衡

放弃「直连的实时性与零中间费用」，换取**初期渠道铺开速度与单一集成面**。
这是「先收敛接入面、留演进位」的决策：集成商是初期唯一的 DMS 入站/出站通道，
直连能力由 per-partner Adapter 天然承载，切换成本被压到一个 Adapter 的实现量。
