## 背景

- 公司既定口径（用户长期工作方式）：**文件/附件存储继续用本地文件系统**，
  不为了「完美」引入 MinIO / S3 / 对象存储等外部组件；floorplan 的 `ADR-业务口径总定源.md §12.1`
  亦写明「不引入外部组件：文件存储继续本地，不引 MinIO/S3/对象存储、不引 MQ/Seata」。
- floorplan 的 `infrastructure/integration/` 虽有 `S3AttachmentStorage` + `LocalAttachmentStorage`
  两套真实实现与条件类，但 `PROGRESS §8.2` 记录「按用户要求继续用本地」。
- 本项目附件面更大：身份核验材料、收入证明（工资薪金扣缴凭单等）、法定书面文件、所有权解除文件四件套、
  入金明细 CSV、征信报文 —— 且**大量含 PII**，引入外部对象存储会扩大委托方与数据驻留的合规面
  （`R01 §5.2` L-7 / L-16、`[待定源 C-06]`）。
- 事件一致性方面，公司中台已有成熟的 Transactional Outbox（DB 轮询），无需 MQ / Seata。

## 结论

1. **附件一律本地文件系统**：`data/attachments/` 按 `biz_id` 分目录；DB 只存
   `core.attachments.relative_path` + `sha256` + `size_bytes`（`R06 §4.8`），**不存对象存储 key**。
   复用 `AttachmentStorage` / `DirectUploadEndpoint` **接口与本地实现**，**不启用 S3 实现**。
2. **原始文件必须留存**：合同/书面文件/身份核验材料的原件随业务单留存，不能只存解析结果（自证需要）。
3. **不引入 MQ / Seata / 分布式事务**：跨模块状态同步走 outbox（本地消息表 + DB 轮询），
   同步只用于 fail-closed 门禁（`R02 §7`）。
   —— **2026-11-23 修订（`ADR-RF-014`）**：本条的「不引入 MQ」部分已失效——
   引入 RocketMQ 作为**削峰缓冲层**（outbox 仍是唯一事务真相源，不引分布式事务、不引 Seata），
   且 **MQ 上只允许出现密文信封**（含个人信息的载荷先加密再入队）。
4. **不引入 Redis 作为缓存**（起步）：只保留 `InMemoryDistributedLock`；
   若将来引入 Redis，只做幂等去重与短时锁，**绝不缓存账本/PII/审查结果**。
5. 本地文件受 **OS ACL + 应用鉴权双重控制**；PII 附件不对外直出，访问走 `R08 §5` 管控。
6. 本地存储的运维约束明确写入 `AGENTS.md`：备份、磁盘容量监控、路径不入库明文账号、
   测试夹具用 `TEST-*` 占位，**禁止真实个人信息**。

## 后果

**变容易**：无外部组件依赖，本地可跑、可备份、可审计；PII 不出本机，委托方与跨境评估面最小；
与 floorplan 运维方式一致；起步验证成本低。

**变难**：单机磁盘是容量与可靠性瓶颈；多实例部署需要共享存储方案（届时需重新评审）；
附件备份/容灾要自己做；水平扩展时本地文件成为状态，需要迁移策略。

**明确不做**：不启用 `S3AttachmentStorage`；不引 MinIO / S3 / 对象存储；不引 MQ / Seata / Kafka；
不把附件内容写进 outbox payload 或应用日志（`ADR-RF-007`）。

## 被拒选项与理由

| 选项 | 理由 |
|---|---|
| 引入 S3/MinIO 做「生产级」附件存储 | 违反公司既定口径；扩大 PII 委托方与数据驻留合规面；起步不需要 |
| 把附件内容塞进数据库 `BYTEA` | 库膨胀、备份困难；且原件留存与解析结果分离的设计会退化 |
| 引入 MQ 替代 outbox | 公司中台 outbox 已成熟且可重放；MQ 增加运维与一致性成本 |
| ~~引入 MQ 做削峰~~ | **2026-11-23 已被 `ADR-RF-014` 取代**：作为 outbox 之上的削峰缓冲层引入 RocketMQ，
但 outbox 仍是唯一事务真相源、MQ 不参与事务；且 MQ 上只允许出现密文信封（明文 PII 一律不入队） |
| 引入 Seata / AT 模式 | 全局锁 + 回滚日志在金融账务上风险过高（floorplan 目标架构明确不用） |

## 权衡

放弃「云原生弹性存储」，换取**合规面最小、运维最简单、与公司口径一致**。
这是一个有意识的取舍：当附件主要是含 PII 的文件时，「少一个外部系统」本身就是安全收益。
