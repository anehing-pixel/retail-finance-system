# R09 · 接口与事件契约

> **定位**：内部端点、错误码、**事件白名单（禁个人信息）**、幂等与 Feign 门禁契约。契约冻结后是 S1+ 的编码依据。
> 本文最关键的一节是 **§5**：`outbox_events` 表跨服务共享且 `SENT` 行永久保留，
> **任何个人信息进入 payload 都是合规事故**（`R03 §4` 切断点 ①、`ADR-RF-007`、INV-4）。
> 本文采用 **Spring Cloud 微服务口径**（`ADR-RF-001`、`R02 §3`）：同步调用只用于代付前门禁，其余状态同步走 outbox。

## 1. 引用口径

- 响应统一 `ApiResponse<T>`：`{code, message, data, traceId, details}`；**`202` ≠ 业务成功**。
- `traceId` 由网关生成/透传，贯穿日志、审计、outbox、`call_logs`；Feign 门禁必须透传。
- 错误码以 `R00 §3.5` 为唯一命名源，单一枚举 `domain/exception/ErrorCode`。
- 事件名以 `R00 §3.6` 为唯一命名源，常量收口在 `common/contract/OutboxPublisher`。
- **12 个独立部署单元**：同步调用仅限代付前 Feign 门禁（fail-closed，§7），事后状态同步一律走 outbox 事件（§5）；
  跨服务**不共享本地事务**，核心账务闭环留在 `retail-core` 一个本地事务内。见 `R02 §7`、`ADR-RF-001`。

## 2. 通用约定

| 项 | 约定 |
|---|---|
| 路径前缀 | 内部 `/api/**`（网关 18081）；外部 `/external/**`（DMZ 18091） |
| 认证 | 员工侧 / 客户侧两套 JWT，各服务本地验签、零信任；网关只路由不验签 |
| 权限 | 写接口标 `@RequirePermission`；401 认证失败 / 403 授权失败严格区分；SOD → `RF_AUTH_003` |
| 跨服务 | Feign 门禁透传 `traceId` + JWT（§7）；outbox 消费上下文无 JWT / HTTP 上下文，只处理本地状态 |
| 幂等 | **四层**：① 分布式锁（跨实例串行化，`ADR-RF-013`）② `Idempotency-Key` 头 + 请求指纹 ③ DB 唯一索引 ④ 业务唯一键；键同体不同 → `RF_CONFLICT_001`；锁不可用 → `RF_LOCK_002`（503，fail-closed 拒写） |
| 金额 | 一律整数日元（`long`），JSON 中为数字，不用字符串、不用小数 |
| 时间 | ISO-8601 + JST；业务日期 `yyyy-MM-dd` |
| 分页 | `page` / `size` / `sort`；默认 `size=20`，上限 200 |
| 状态变更 | 只通过领域状态机方法；接口不暴露「直接改 status」的通用端点 |
| 脱敏 | 所有响应默认脱敏；个人信息全量需 `PII_VIEW_FULL` + 用途 + 留痕（`R08 §5`） |

## 5. 事件契约与 payload 白名单（**核心红线**）

### 5.1 事件清单（与 `R00 §3.6` / `R04 §6` 一致）

> 生产方 / 消费方用 `R04 §6` 的限界上下文编号（BC-x），服务归属见 `R02 §5`；
> 事件只做**事后状态同步**，不承担同步门禁（门禁走 §7 Feign）。

| 事件 | 生产方 | 消费方 | `aggregate_key` |
|---|---|---|---|
| `APPLICATION_SUBMITTED` | BC-1 | BC-2 / 审计 | `applicationId` |
| `IDENTITY_VERIFIED` | BC-2 | BC-3 / 审计 | `verificationId` |
| `CONSENT_GRANTED` / `CONSENT_WITHDRAWN` | BC-2 | BC-3 / BC-4 / 审计 | `consentId` |
| `CREDIT_INQUIRY_COMPLETED` | BC-4 | BC-3 / 审计 | `inquiryId` |
| `UNDERWRITING_APPROVED` / `UNDERWRITING_DECLINED` | BC-3 | BC-5 / 审计 | `caseId` |
| `CONTRACT_SIGNED` | BC-5 | BC-6 / 审计 | `contractId` |
| `DISBURSEMENT_PAID` | BC-6 | 对拍 / 审计 | `disbursementId` |
| `VEHICLE_DELIVERED` | BC-10（投影） | BC-8 / 审计 | `applicationId` |
| `TITLE_RETENTION_REGISTERED` | BC-8 | 审计 | `titleId` |
| `REPAYMENT_RECEIVED` | BC-7 | BC-6 / BC-9 / 审计 | `paymentRef` |
| `LOAN_SETTLED` | BC-6 | BC-8 / 报送 / 审计 | `loanId` |
| `RELEASE_DOCUMENTS_ISSUED` | BC-8 | 审计 | `releaseOrderId` |
| `TITLE_RELEASE_REGISTERED` | BC-8 | 报送 / 审计 | `releaseOrderId` |
| `DPD_CHANGED` | BC-9 | 报送 / 审计 | `loanId` |
| `CREDIT_BUREAU_REPORT_SENT` | BC-4 | 审计 | `reportId` |

**`TITLE_RETENTION_REGISTERED` 的发布口径（用户裁决 2026-11-23）**：登记事件只在**操作员正式登记**发生时发布一次；
若该债权此前已由 `LOAN_SETTLED` 兜底建单（**挡板占位行**，`vin=UNKNOWN-<loanId>`），正式登记命中该行时
**订正 VIN 并补发一次**登记事件（同一 `titleId`）——占位行不是「已登记」的业务事实，不补发则证据链缺这一环。
订正走**乐观锁 + 占位 VIN 条件**，**并发/重放只订正一次、只补发一次**（§5.4 幂等铁律）；
**真实登记行**重复登记幂等返回、不重复发事件。订正只作用于占位行，**不改状态**，
故不弱化 INV-3「`REGISTERED → RELEASE_REGISTERED` 唯一入口是外部登记回执」。详见 `R04 §6`。

### 5.2 payload **允许键白名单**（除此以外一律拒绝）

| 类别 | 允许键 |
|---|---|
| 元数据 | `eventId` · `eventType` · `occurredAt` · `traceId` · `schemaVersion` |
| 业务主键 | `applicationId` · `contractId` · `loanId` · `caseId` · `consentId` · `inquiryId` · `verificationId` · `disbursementId` · `titleId` · `releaseOrderId` · `paymentRef` · `reportId` · `dealerPartnerId`（**均为内部 ID，非个人信息**） |
| 状态/结果 | `status` · `outcomeCode` · `reasonCode` · `scheme` · `ruleVersion` · `stage` |
| 金额/日期 | `amount` · `currency`(固定 `JPY`) · `bizDate` · `dueDate` |
| 技术字段 | `idempotencyKey` · `source`(AUTO/MANUAL) · `attempt` |

### 5.3 **禁止键清单**（命中即拒绝发布，INV-4）

```
name / fullName / kana / address / birthDate / phone / email
employer / annualIncome / income / identityDocumentNo / documentNumber
accountNo / bankAccount / myNumber / encrypted_* / *_pii
vinOwnerName / customerName / rawPayload / attachments / documentContent
以及任何未列入 §5.2 白名单的键（默认拒绝，不是默认放行）
```

**实现要求**：
- 发布前由 `OutboxPublisher` 做**白名单校验**（默认拒绝策略），发现禁键抛异常并写审计，**不写库**。
- 需要客户信息时，只经**事件白名单内的业务主键**间接关联（如 `applicationId`），消费方按需经 `PiiService` 授权读取；
  **白名单是穷举默认拒绝（INV-4）**：`customerId` 等未登记键一律不进 payload（S2-W3 实测口径——
  事件消费方持业务主键即可回查，无需客户 ID 直传；若未来确需登记，走契约变更流程加白）。
- 原始报文 / 附件内容**绝不进事件**；需要传递时只传 `attachmentId` / `ref`。
- `JsonPayloadReader` 改造为 `requireBizKeyAndTraceId(bizKeyName)`（**切断 floorplan 的 `requireVinAndTraceId` 硬编码**，见 `R03 §4`）。
- 事件表 `SENT` 行永久保留 ⟹ 一旦写入个人信息无法「撤回」，只能事后补救。**预防是唯一手段**。

### 5.4 消费侧三铁律

1. **必须幂等**：消费幂等键 `(event_id, consumer)`；`consumer` 用服务/模块名，改名 = 历史幂等失效。
2. **不许吞异常**：吞掉会让状态显示 DONE 但实际没做（假绿）；失败计数 3 次 → `DEAD` 并推进游标。
3. **不许跨服务调用**：消费上下文无 JWT / HTTP 上下文，只处理本地状态，**不得反向发 Feign**（§7.3）。

`CONSENT_WITHDRAWN` 是**合规刚性事件**：必须秒级送达 BC-3 / BC-4 以阻断后续查询与报送（INV-5）。

## 6. `aggregate_key` 规则与幂等三层

| 层 | 规则 |
|---|---|
| 发布端 | `(event_type, aggregate_key)` 用 `INSERT ... WHERE NOT EXISTS` 去重；`aggregate_key` **一次发生一个值**，禁用裸 `vin` / `traceId` / `event_type` 单键 / 每次换新值 |
| 框架层 | `core.event_consumptions(event_id, consumer)` 主键幂等 |
| 业务层 | 业务唯一键（`uk_disb_loan` / `uk_alloc_payment` / `uk_batch_job_date`）兜底 |

HTTP 写接口作用域：申请 / 代付 / 合同 为全局唯一；入金核销按 `paymentRef`；批处理按 `(jobName, bizDate)`。

**并发窗口与分布式锁（`ADR-RF-013`）**：唯一索引只能覆盖「键相同」的场景；
时间窗去重（同一人 + 同一车辆 + 窗口期）与「外部方换 nonce 重推同一业务回执」需要跨实例串行化手段 →
受保护写路径加**分布式锁**：锁键 `retail:lock:{用途}:{业务标识摘要}`（不落明文业务标识），
锁在**事务提交后**释放，临界区**锁内重查**。
锁**不是正确性来源**：同幂等键并发最终仍由 `uk_app_idempotency` 兜底，
同一业务回执最终仍由 `uk_receipt_order_authority_ref`（V19）兜底；
Redis 不可达即 `RF_LOCK_002` 拒绝写，**不降级放行**。

## 7. Feign 契约（**微服务同步门禁，S1 起即为现状**）

本仓直接采用 Spring Cloud 微服务（`ADR-RF-001`、`R02 §3`）：**Feign 不是「将来拆分时才启用」的预留契约，
而是 S1 起就必须落地的同步门禁**。事后状态同步不在此链路，一律走 §5 的 outbox 事件。

### 7.1 唯一允许的同步调用：代付前门禁（fail-closed）

```
retail-core 代付前 ──Feign──> contract-service      合同已生效且法定书面文件已交付？
                  ──Feign──> customer-service      同意有效且未撤回？
                  ──Feign──> underwriting-service  审查已批准？
              三者均返回明确 OK → retail-core 本地事务代付（行锁 + uk_disb_loan 唯一约束）
              任一 UNKNOWN / 超时 / fallback / 非 2xx → 拒付并整体回滚
```

- **fail-closed**：`UNKNOWN` 不视为通过；严禁用 fallback 返回「默认放行」（反模式 A-14、`R10 A14`）。
- 门禁调用必须透传 `traceId` 与员工 / 客户 JWT（`R02 §7`、`R08 §5`），下游零信任本地验签。
- 门禁**只读判定、不跨服务写状态**；代付后的状态同步走 outbox（§5），不在此链路发第二次 Feign。
- 核心账务闭环（债权 / 还款计划 / 代付 / 入金核销 / 结清）留在 `retail-core` **一个本地事务**内，不引分布式事务。

### 7.2 契约冻结规则

- 返回 `ApiResponse<T>`（**禁止裸对象**，否则 Jackson 把 `{code,message,data}` 贴到 DTO 全 null 且 200）；
- `url = "${retail.clients.<key>.url:}"` 双模，空串回退 `lb://服务名`；属性键小写单词；
- 调用方启动类 `@EnableFeignClients(basePackages = "com.company.retail.common.contract")`；
- 契约常量收口在 `com.company.retail.common.contract`，冻结源 = 本文 + `PROGRESS §2` 登记；

### 7.3 禁止事项

- 禁止在 outbox 消费上下文里发 Feign（§5.4 铁律 3：消费上下文无 JWT / HTTP 上下文）；

- 禁止把 12 个服务「都起来了」当成链路已通：必须用走网关冒烟证明门禁 + outbox 可达（反模式 A-16）。
