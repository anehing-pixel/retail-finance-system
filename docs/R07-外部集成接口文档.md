## 2. 五条架构约束（沿用公司基线，按 C 端强化）

### 2.1 入口分离（DMZ 独立进程）

```
api-gateway :18081（内部：员工运营 / 客户 BFF）
   └ JWT 验签 + RBAC；零信任（网关不验签，鉴权下沉）
external-api :18091（DMZ：数据集成商（DMS 中转）/ 征信局 / 银行 / eKYC / 登记代办）
   └ per-partner HMAC + mTLS/专线 + nonce + IP 白名单 + 限流；独立 DB role
```

- 两个入口**鉴权模型完全不同，不得混用**；在同一应用里加 `/external/**` 路径，网络隔离形同虚设。
- `external-api` 只授 `integration` schema，**不授 `core` / `pii`**（`R06 §3`）。
- 外部接口**暴露字段最小化**：不暴露内部 ID、审查规则、风险等级、PII 明文。

### 2.2 防腐层（ACL）强制

```
外部 DTO → [PartnerAdapter: 验签/字段映射/枚举翻译] → 内部 Command → application → domain
```

每个 partner 一个 Adapter；外部字段变更不污染核心模型。DMS 的「车型代码」「审查状态」、
征信局的「异议标记」等外部编码一律翻译成本系统枚举（`R00 §3.4`）。

### 2.3 Outbound 韧性 + 人工重触发

标配：超时、指数退避重试、幂等键、熔断、`integration.outbound_tasks` 状态机。
**关键**：对方接口挂了要能在运维界面点「重新推送」，不能让业务停摆。
所有调用落 `call_logs`（请求/响应/耗时/结果/traceId），便于排查与重放。

### 2.4 对账是兜底，不是补充

跨系统**没有分布式事务**，以下逐笔对账：

| 对账项 | 本系统侧 | 对方侧 |
|---|---|---|
| 代付 | `core.disbursements`（PAID） | 银行汇出明细 |
| 入金核销 | `core.payment_allocations` | 银行入金明细 / 代收机构结果 |
| 征信报送 | `integration.credit_bureau_reports` | 征信局受理回执 |
| 所有权解除 | `core.registration_receipts` | 运输支局登记事项 |

### 2.5 人工路径是一等公民

同一业务能力同时支持「自动」与「人工」，两条路径汇入**同一个内部 Command**，下游无感知：

```
征信查询：专线 API（自动） / 人工查询 + 结果录入 + source=MANUAL
入金明细：文件/API（自动） / 網銀 CSV 导入 + 逐行报错可修正（人工）
解除回执：机构回执（自动） / 我方见证代录（**仅中间态，不得代替权威回执**）
```

### 4.1 通用报文规范（我方提议协议 v1 · 各通道共用）

> **三层状态口径**：🌐 预设（仅有能力设想）→ **🟦 我方提议协议 v1（Proposal，本节）**：调研回收前的对外谈判基线与 Adapter 开发依据 → ✅ 已对齐（对方确认后）。对方实际报文与本协议的差异，一律由 PartnerAdapter 翻译承接，**不改核心模型**。

**传输与编码**

- HTTPS（TLS 1.2+，禁用 TLS 1.0/1.1）；字符集 UTF-8；`Content-Type: application/json; charset=utf-8`。
- 时间一律 ISO-8601 带偏移量（如 `2026-11-23T10:00:00+09:00`），全系统 JST（`R00 §5`）。
- 金额一律 **BIGINT 整数日元**（无小数、无千分位分隔符）；禁止 double/浮点参与金额（B-8）。
- 日期 `YYYY-MM-DD`；布尔 `true/false`；枚举大写下划线（`R00 §3.4`）。
- 文件通道（扣款/入金/代收结果）默认固定长记录；对方仅支持 CSV 时按 §4.11 / §4.12 的映射降级。

**信封（所有消息共用）**

```json
{
  "protocol_version": "1.0",
  "message_id": "UUID，发送方生成，全局唯一",
  "idempotency_key": "业务幂等键，写操作必填",
  "occurred_at": "2026-11-23T10:00:00+09:00",
  "partner_code": "INTEGRA-01",
  "payload": {}
}
```

**响应体**：Inbound 统一 `HTTP 202` + `{"receipt_id", "accepted_at", "duplicate": false}`，业务结论异步回传；
查询型接口（资质预审、征信查询）同步 `200` 返回业务结果。
**错误体**：`{"code", "message", "receipt_id", "retriable"}`；`code` 只用 `R09 §4` 已注册错误码
（`RF_PTNR_*` / `RF_VALID_001` / `RF_CONFLICT_001` / `RF_DMS_*` / `RF_BUREAU_001` 等），**不新开错误码家族**。

**通用请求头**（DMZ Inbound）：`X-Partner-Code` · `X-Nonce` · `X-Timestamp` · `X-Key-Version` · `X-Signature` · `Idempotency-Key`（§5）。
**Outbound 重试基线**：指数退避 1m/5m/30m/2h/6h，5 次后转 `integration.outbound_tasks` 人工重触发（§2.3）。

### 4.2 P-01 · DMS 资质预审（I-11，Inbound，同步查询）

`POST /external/dms/pre-screens` · 幂等锚点 `Idempotency-Key + (customer_hash, window)` · **不触发征信查询（RB-1）**。

| 请求字段 | 必填 | 说明 |
|---|---|---|
| `dealer_code` / `store_code` | ✓ | 加盟店与门店编码（集成商主数据） |
| `customer.customer_hash` | ✓ | 身份证号加盐 SHA256（盐随集成商密钥协商，`R06 §4.1` 同源） |
| `customer.birth_date` / `annual_income_band` | ✓ | 年龄段校验与收入档位（枚举，不收精确收入） |
| `desired.product_type` | ✓ | `NEW_CAR_LOAN` / `USED_CAR_LOAN`（双形态，C-01） |
| `desired.amount` / `desired.term_months` | ✓ | 意向金额（BIGINT）/ 期数（1–120） |

响应（同步 200）：`pre_result`（`PASS`/`REVIEW`/`FAIL`）· `max_amount_hint`（BIGINT，可空）· `reason_codes[]` · `expires_at`。
错误：`RF_DMS_001` 资质不符 · `RF_VALID_001` 参数错。

### 4.3 P-02 · DMS 正式授信申请（I-01，Inbound，异步受理）

`POST /external/dms/applications` · 幂等锚点 `Idempotency-Key + (customer_hash, vehicle_ref, window)` · 响应 202 + `receipt_id`。

| payload 分块 | 字段 | 说明 |
|---|---|---|
| `application` | `application_ref`（对方单号）· `product_type`（双形态，C-01） | `product_type` 缺失即拒（`RF_DMS_003`） |
| `customer` | `name` · `name_kana`（全/半角+片/平假名）· `birth_date` · `postal_code` · `address` · `phone` · `identity_doc_type` / `identity_doc_no` · `annual_income` · `employment_type` · `existing_loans_count` / `existing_loans_monthly_total` | PII 块经 ACL **直落 `pii` 域**，DMZ 表只存脱敏引用（§6，A-12） |
| `loan` | `vehicle_price` · `down_payment` · `loan_amount` · `term_months` · `first_payment_month`（`YYYY-MM`） | 金额均 BIGINT |
| `vehicle` | `vehicle_ref` · `vin`（可空，C 端非业务主键，A-13）· `make` · `model` · `grade` · `model_year` · `mileage_km` · `first_registration_date` | 车辆重复申请 → `RF_DMS_002` |
| `consent` | `use_of_pii` · `third_party_provided`（两布尔，均须 `true` 才受理） | 同意留痕先行（B-5），落地 `consent_id` |

### 4.4 P-03 · 审查结果通知（I-02，Outbound → 集成商 → DMS）

`POST {integrator}/rf/underwriting/result` · 幂等锚点 `application_no` · 触发：审查终态（`R04 §3`）。

| 字段 | 说明 |
|---|---|
| `application_ref` / `application_no` | 对方单号 / 我方申请号 |

## 5. DMZ 安全：签名、密钥轮换与校验顺序

### 5.1 规范化串（HMAC-SHA256）

```
canonical = METHOD + "\n"
          + PATH + "\n"
          + timestamp + "\n"
          + nonce + "\n"
          + key_version + "\n"
          + SHA256(body)

signature = Base64(HMAC-SHA256(partner_secret, canonical))
```

请求头：`X-Partner-Code` · `X-Nonce` · `X-Timestamp` · `X-Key-Version` · `X-Signature` · `Idempotency-Key`。

> 相对 floorplan 现有 `PaymentWebhookVerifier` 的四点强化（其现状为全局单密钥 + 无 nonce + 未覆盖 body 摘要）：
> ① 纳入 `METHOD/PATH/SHA256(body)`；② `nonces` 表真正防重放；③ **per-partner 密钥 + `key_version` 轮换宽限**；
> ④ 独立进程独立端口。征信局专线若要求 mTLS/机构认证，走**独立 Adapter**，不复用 HMAC 通道。

### 5.2 校验顺序（不可调换）

| 序 | 校验 | 失败 |
|---|---|---|
| 1 | 时间戳 ±300s | `RF_PTNR_001` |
| 2 | nonce 未使用（写 `integration.nonces`） | `RF_PTNR_002` |
| 3 | 签名（常量时间比较） | `RF_PTNR_001` |
| 4 | partner 状态 / scope / IP 白名单（**DMZ 入站侧限流未实现，口径待定**，`R07 §7`；入站洪峰由**边缘 Nginx 按来源 IP 泄洪**承担，DMZ 进程内不重复限流；内部网关另有令牌桶按路径配额，见 `ADR-RF-012` 与 `R02 §3.3`） | `RF_PTNR_003` |
| 5 | 幂等（`inbound_messages`） | `RF_CONFLICT_001`（返回首次结果） |

**为什么是这个顺序**：先验时间戳和 nonce 能在最廉价处挡掉重放；签名放第 3 位避免对伪造请求做无谓的 partner DB 查询；
partner scope 与幂等最后，保证「验明正身」后才谈业务。

### 5.3 密钥与凭据

- 每 partner 独立密钥，存 `integration.partner_credentials.secret_ref`（**不明文**，指向密钥管理设施）。
- `key_version` 轮换支持**双版本并存宽限期**，旧版本只读至存量报文处理完。
- 生产禁用全局单密钥；CORS 收紧到 partner 白名单（floorplan 现为 `*`，是已知缺口）。

## 8. 排期风险提示

- **征信局接入是长周期项**（审查 + 专线 + 报文联调），应在 **S0 就启动**，不能等 S3 才开始（`R02 §11 R-2`）。
- DMS 对接：初期经**数据集成商**收敛为单一 partner（`ADR-RF-011`）；**数据延迟与渠道单点**是新增风险，
  对账兜底与人工路径必须长期并存；后期核心集团按切换触发器转直连（per-partner Adapter 承载）。
- 车辆登记/名义变更对民间**极可能无开放接口**，按「全人工 + 回执权威判定」设计。
- 工期应按「**最坏情况：大部分人工**」估算；联调结果回收后重估。
- 系统不凭空对接：**2026-11-24 起全部通道已由我方内部裁决回填（🟦，§7 ☑）**；联调前仍**不实现真实对接**，
  接口预留 + 人工留痕；联调差异只改 Adapter。
- 提议协议 v1 + §7 内部裁决只降低**联调期协议协商成本**；Adapter 开发可按裁决先行，
  实际报文差异在联调期消化，**不影响核心模型与领域状态机**。
