Staff Console

员工运营台

端到端验证 S1–S12：员工登录 → 客户注册 → 身份核验 → 申请 → 审查 → 合同 → 账务 → 还款 → 结清 → 解押 → 贷后。

S1–S12
会话对象
S1

员工登录

POST /gw/api/auth/staff/login —— token 是后续所有步骤的前置。

S2

客户注册（PII 加密落库）

POST /gw/api/customers —— 电话号按时间戳自动生成，可改姓名。

S3

身份核验（MANUAL 人工通道）

发起 → 提交驾照材料 → 开始核验 → 人工审核通过 → VERIFIED。

S4

征信同意取得

POST /gw/api/consents（purpose=CREDIT_INQUIRY）→ 有效性查询。

S5

申请提交（含幂等重放验证）

POST /gw/api/applications，Idempotency-Key 重放应返回 replayed=true 与同一申请号。

S6

审查域（建案→征信→支付能力→APPROVED）

G3 同意门禁真实生效；征信走 CIC 挡板；INQUIRY_DONE 由事件驱动（页面轮询案件状态）。

S7

合同域（书面交付→签订→冷静期→EFFECTIVE）

两份法定书面留痕 → DOCUMENTS_DELIVERED → 签订 → 冷静期确认 → 查询代付门禁。

S8

账务（建债权→还款计划→三门禁代付）

G8 门禁 fail-closed：合同/审查任一不符即拒（页面含两个负例按钮）。

S9

还款（到期滚转 job → 逐期核销 → 余额对拍）

schedule-due-rollup 滚至末期后逐期 POST /gw/api/payments，每期后刷新计划与余额。

S10

结清（试算 → NORMAL settle）

GET settlement-quote → POST settle → LOAN_SETTLED 事件驱动解押建单。

S11

解押（保留登记 → 事件建单 → 文件四件套 → 外部回执闭环）

代录（INTERNAL_WITNESS）≠ 完成；经销商自证被拒（X-10）；仅 EXTERNAL_REGISTRY 回执可闭环。

S12

贷后（DPD 快照 + 对拍）

/svc/api/jobs/dpd-snapshot（直连段，与 e2e 同口径）+ /gw/api/recon/run。

ALL

全链路 · 一镜到底

从登录到解押闭环顺序执行 S1–S12（幂等键用本次会话时间戳，可重复跑）。

Customer Self-Service

客户自助

客户主体开发桥登录与本人脱敏视图；员工 token 访问将被拒绝，用于验证双主体隔离。

ID

客户登录（开发桥）

POST /gw/api/auth/customer/login，用户名 = customerId（RETAIL_CUSTOMER_DEV_LOGIN=true）。

ME

我的脱敏视图

GET /cust/api/customer-self/me —— 姓名/电话脱敏返回，员工 token 访问会被拒（主体隔离）。

Documentation

说明

本地验证页的链路口径与使用提示。

这是什么

本地验证用前端控制台：把 e2e_w8.py 的 98 断言链路做成可点击页面。 所有请求经本页（18082）同源代理转发：/gw/**→网关 18081， /svc/**→servicing 8098，/cust/**→customer 8092（与 e2e 直连段口径一致）。

右下角日志面板记录每次请求的方法 / 路径 / 状态 / 耗时。

口径提示

① 幂等键每次会话唯一，可重复跑；② 事件驱动步骤（INQUIRY_DONE、解除建单）页面用轮询等待； ③ 代录回执只到 MANUAL_RECORDED，保留态不变，必须外部登记回执才闭环（B-6 / C-11）。
